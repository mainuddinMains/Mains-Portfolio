# CLAUDE.md

Guidance for Claude Code when working in this repository. Read `README.md` for user-facing
setup and `AGENTS.md` for the Next.js version notice.

## Project goals

A personal developer and research portfolio for an MS Computer Science student. It covers
software projects, work experience, AI/ML and HPC research, conferences, skills, education and
hobbies.

- The owner manages **all content through Sanity Studio at `/studio`**, never by editing code.
  Any new content must be editable there.
- The site supports images, photo galleries with captions, and multiple YouTube videos per item.
- The CMS must stay **replaceable**: UI code never depends on Sanity.
- The app must **build and run without Sanity credentials** (CI, fresh clones, previews).
- Current phase: foundation. Visual design is intentionally minimal. Don't do a full redesign
  unless asked.

## Architecture

```
sanity.config.ts         Studio config ("use client"; structure, singleton rules)
src/app/                 Routes only, kept thin
  layout.tsx             <html>/<body> shell + metadata
  (site)/                Public pages with header/footer
  studio/[[...tool]]/    Embedded Studio (outside (site) so it is full-screen)
  api/revalidate/        Sanity webhook → revalidateTag
src/domain/content.ts    CMS-agnostic domain types: the contract for all UI
src/lib/content/
  index.ts               PUBLIC content API ("use cache" file); pages import from here
  repository.ts          ContentRepository interface
  sanity-repository.ts   Sanity implementation
  fallback-repository.ts Placeholder implementation used when Sanity is not configured
  source.ts              Selects the implementation
  tags.ts                CONTENT_TYPES + cache tag helpers
  static-params.ts       toSlugParams() for generateStaticParams
src/sanity/
  env.ts                 Env parsing; never throws
  schemas/               objects/ (reusable), documents/, fields.ts (shared field helpers)
  lib/                   client (lazy), GROQ queries, raw → domain mappers
src/components/          Content-agnostic UI: layout/, media/, ui/
src/features/<domain>/   Domain-specific UI (projects, research, conferences, ...)
src/config/              Static app config (navigation)
```

**Data flow:** page → `@/lib/content` → `ContentRepository` → GROQ → mapper → domain type → UI.

### Dependency rules

- Pages and components import content **only** from `@/lib/content` and types **only** from
  `@/domain/content`. Never import `sanity`, `next-sanity`, or `@/sanity/*` from
  `src/app/(site)`, `src/components` or `src/features`.
- `@/sanity/*` is the only place that knows Sanity document shapes. Mappers turn GROQ results
  into domain types: nulls become `undefined`, arrays default to `[]`, and YouTube IDs are
  parsed there.
- Server-only modules (client, repository, source) start with `import "server-only"`.

## Next.js 16 + Cache Components: gotchas

This Next.js version differs from older training data. Check
`node_modules/next/dist/docs/` before using an unfamiliar API.

- `cacheComponents` is on. **Don't use** `export const dynamic`, `revalidate`, `fetchCache`,
  `dynamicParams` or `runtime`: they are removed and break the build.
- Caching uses `"use cache"` + `cacheTag(contentTag(type))` + `cacheLife(...)`. All functions in
  `src/lib/content/index.ts` follow the same pattern; keep it that way.
- Anything non-deterministic in a server component (`new Date()`, `Math.random()`) must sit in a
  `"use cache"` scope or behind `<Suspense>`, otherwise prerendering fails (see `SiteFooter`).
- `generateStaticParams` must return **at least one** entry. Always use
  `toSlugParams(items)`, which returns a placeholder slug that resolves to `notFound()`.
- `revalidateTag(tag, "max")`: the second argument is required.
- `next/image` uses `preload` (not `priority`). Use `CmsImage`, which applies the Sanity CDN
  loader.
- Typed route props: `PageProps<"/route/[slug]">` and `LayoutProps<"/">` are global types
  generated by `next typegen`.

## Recipe: adding a new content type

1. Domain type in `src/domain/content.ts`.
2. Sanity schema in `src/sanity/schemas/documents/<name>.ts` using helpers from `fields.ts`
   (`slugField`, `galleryField`, `videosField`, `coverImageField`, ...). Export it from
   `documents/index.ts`.
3. GROQ query in `src/sanity/lib/queries.ts` (wrap with `defineQuery`; reuse the `image`,
   `galleryImage`, `media`, `body` projections).
4. Mapper in `src/sanity/lib/mappers.ts` + tests in `mappers.test.ts`.
5. Add methods to `ContentRepository`, then implement them in **both** `sanity-repository.ts` and
   `fallback-repository.ts`.
6. Add the type to `CONTENT_TYPES` in `tags.ts`. The webhook and schema tests rely on it.
7. Add a cached function to `src/lib/content/index.ts`.
8. UI in `src/features/<name>/`, a route in `src/app/(site)/`, and a nav entry in
   `src/config/navigation.ts` if needed.
9. Run `npm run check` and `npm run build`.

For singleton documents, also add the type to `singletonTypes` in `src/sanity/schemas/index.ts`
and give it a fixed-id entry in `src/sanity/structure.ts`.

## Coding conventions

- TypeScript strict. Avoid `any`; the exception is raw CMS payloads in mappers (already
  scoped with an eslint-disable block).
- File names are kebab-case (`photo-gallery.tsx`). Use named exports, except where Next.js
  requires a default export (pages, layouts) and `sanity.config.ts`.
- Use Server Components by default. Add `"use client"` only for interactivity or browser-only
  APIs (nav state, `next/image` with a loader).
- Formatting is Prettier only (100 cols, double quotes, trailing commas, Tailwind class sorting).
  Don't hand-format; run `npm run format`.
- Style with Tailwind using theme tokens from `globals.css`: `bg-background`, `text-foreground`,
  `text-muted`, `bg-surface`, `border-border`. Avoid hard-coded colors so dark mode keeps
  working.
- Accessibility: every image needs alt text (schemas enforce it), use semantic elements
  (`figure`/`figcaption`, `nav`, `article`), and external links get
  `rel="noopener noreferrer"`.
- Media: render images through `CmsImage`, galleries through `PhotoGallery`, and videos through
  `YouTubeEmbed`/`VideoList`. Validate and parse YouTube URLs with `src/lib/utils/youtube.ts`.
- Tests sit next to the code as `*.test.ts`. Vitest runs in the node environment and stubs
  `server-only`. Prioritise tests for pure logic (mappers, utils, route handlers).

## Security and environment

- Only `NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET`,
  `NEXT_PUBLIC_SANITY_API_VERSION` and `NEXT_PUBLIC_SITE_URL` may be public. Tokens and secrets
  (`SANITY_API_READ_TOKEN`, `SANITY_REVALIDATE_SECRET`) must never get a `NEXT_PUBLIC_` prefix.
- Document every new env var in `.env.example` and the README. Missing values must degrade
  gracefully, not throw.
- The Sanity client is created lazily (`getSanityClient()`). Don't create it at module scope,
  because `createClient` throws without a projectId.
- The public site reads the `published` perspective only; drafts must never leak.

## Dependencies

- Don't add `@vitejs/plugin-react`: it causes a Babel peer-dependency conflict with Sanity's
  CLI, and Vitest doesn't need it.
- `@types/node` tracks Node 24 (`.nvmrc`).
- `npm audit` findings come from Sanity CLI and ESLint transitive dependencies. Don't run
  `npm audit fix --force`.
